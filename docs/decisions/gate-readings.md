# 公開前ゲートの項目についての裁定（2026-11-14）

結論: 公開前ゲート（`.claude/skills/write-article/SKILL.md` の G01〜G11）と `docs/tech-writing-pack/checklist.md` の項目について、マネージャーとオーナーが出した裁定を1か所に集めた。ここに書いたものは規則で、書く AI の結論ではない。書く AI は従い、点検する AI は点検の入力として読む。

SKILL.md のゲートの行の文言と、pack の checklist と guides は変えない。この文書は、行の読み方が割れた箇所の読み方と、PR のやり方の決まりだけを書く。ゲートを緩めるものではない。

## 使い方

- 書く AI は、手順8で該当する行を判定する前にこの文書を読む。
- 点検する AI は、原稿、`logs/<slug>/`、SKILL.md、checklist と一緒にこの文書を渡される（SKILL.md の「書く AI と点検する AI」）。
- 裁定どうしや裁定と SKILL.md が食い違うときは、この文書の日付が新しいほうを正とし、食い違いを見つけた側がイシューに書く。
- 新しい裁定が出たら、この文書に1項目足す。足すときは、規則、読む行、出典、日付を書く。

## 1. G07: 関連リンクのリンク先は、予約の時点で公開済み

- 規則: 記事へのリンクは、予約する時点で公開済みの記事を指す。講座のステップの最後の記事は、次のステップの最初の公開済みの記事へリンクする。
- 読む行: G07
- 出典: #13 裁定 A、#33（新しい G07 の文言）
- 日付: 2026-11-14
- 補足: この文書を書いた時点の develop の SKILL.md の G07 は、まだ次の文言のままです。「講座の前後リンク（`prev`、`next` のうち存在するもの）と、既存記事が3本以上なら関連記事への内部リンクが本文にある。リンク先は公開済みか先に予約済み」。#33 の新しい文言が入ったら、行の文言は #33 が正で、上の規則はそれと同じ内容として読む。この文書は行の文言を書き換えない。

## 2. G10: クラウドのセッションでは再判定しない（暫定の扱い）

- 規則: G10 は、クラウドのセッションでは判定し直さない。すでに記録されている判定を残し、G10 の行に日付つきの注記を足す。注記には、この環境ではキーワードの CSV が使えないこと、最終の判定はオーナーの手元でキーワードを集めたあとに出ることを書く。あとで G10 の判定が変わるときは、小さな2回目の作業として直す。
- 読む行: G10
- 出典: #81 のマネージャー裁定、#71（G10 の上書きは確認済み。ただし G10 の行の日付つきの注記は必要）
- 日付: 2026-11-14
- 補足: オーナーの手元から G10 の結果が来るまで、パイロットを含めてどの記事も予約公開しない。

## 3. C25: 60字を超える文の数え方と、URL だけの値

- 規則: 表のセルまたは frontmatter の値が、全体でちょうど1つの URL（ASCII の RFC 3986 の文字だけで、値の全体）のときは、数えずに飛ばし、件数を付けて `[SKIP C25-URL]` の下に一覧にする。URL に文字がくっついているものなど、それ以外はすべて数える。
- 読む行: C25（`60字超の長文を分割した`）
- 出典: #77
- 日付: 2026-11-14
- 補足: pack の writing-lint は表の行を飛ばす。この裁定は、その扱いに合わせて URL だけの値に限って除外を認めるもので、SKILL.md の「判定のために補助のスクリプトを書くときも、checklist とガイドに無い除外を入れない」の例外にあたる。範囲は上の1種類だけで、インラインコードを1字に縮めることや、表やリストを丸ごと飛ばすことは今までどおり認めない。

## 4. C30〜C32: インラインコードは対象外

- 規則: C30（太字のアスタリスク）、C31（em-dash と罫線）、C32（`：` +半角スペースと `／` の並列）の判定では、インラインコードの中身を対象から外す。コードブロックの外でも、バッククォートで囲んだ部分は数えない。
- 読む行: C30、C31、C32
- 出典: #77。根拠は `docs/tech-writing-pack/guides/03-anti-ai.md` の372行目「コードブロック・インラインコード（`` `code` ``）の中の記号は対象外。コードは原文のままが正しい。」（2026-11-14 に行番号と文言を確かめた）
- 日付: 2026-11-14

## 6. G11: ログインの確認はプローブで取る

- 規則: 点検する AI が、`ANTHROPIC_API_KEY` を外して短い `claude -p`（または Agent SDK）の問い合わせを1回動かす。その init メッセージの `apiKeySource` の行、UTC の時刻、`claude --version` の出力を `review.md` に写す。あわせて「書いた AI のサブエージェント自身の init は観測できない」と1文書く。`apiKeySource` が `"none"` でなければ、そこで止めて、費用の問いをオーナーに上げる。
- 読む行: G11（`review.md` の、書いた道具と点検した道具のログインの記録）
- 出典: #81 のマネージャー裁定
- 日付: 2026-11-14
- 補足: アカウント名とメールアドレスは写さない（SKILL.md の「書く AI と点検する AI」）。

## 9. 書く AI の提出前チェック（記事の PR ごと）

記事の PR を出す前に、書く AI は次の4点を確かめる。#81 の記事ごとの指示にも入れる。

- (a) 判定し直したゲートの行ごとに、その行が指すガイドを読み直し、読んだガイドの一覧と日付を `gate.md` の先頭に書く。
- (b) 本文を直したら、`gate.md` と `sources.md` の引用と数を、直したあとの本文に合わせて全部つけ直す。
- (c) コードか、記事に出す出力が変わったときだけ、コードを動かし直す。動かし直したら、`verified_at`、`run_environment`、本文の日付の行をそのログに合わせる。
- (d) 本文に書いたツールの版は、すべてログに版を記録した行がある。

- 読む行: G03、G05
- 出典: #71 のマネージャーの決定
- 日付: 2026-11-14

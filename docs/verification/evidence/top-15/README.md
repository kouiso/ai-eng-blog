# Issue #15 動作確認の記録（トップから記事と講座へ進める）

確認日: 2026-11-27 / ブランチ: `claude/cloud-sweep2-ai-eng-blog-15`（`origin/develop` と同じ）

## 何を確かめたか

issue #15 の「どうなったら終わりか」3項目です。

1. トップに新着の記事が3〜5本出ている（題・講座の番号・公開日）
2. 記事が0本の間は新着の節が出ない
3. 診断の2つ目の答えから `/tag/llm-eval` へ進める

## 手順

どちらも `npm run build` のあと `npx wrangler dev --local --port 8787`（`--persist-to` はスクラッチ側）で動かしました（`npm run dev` は使っていません）。DB はローカルだけで、本番には触れていません。

1. `npm run build`（成功）。
2. 空の DB で起動し、`/` が 200 になるのを待つ。`#latest` が無いことを 390px と 1440px で確かめる。同じ空の DB で、診断の2つ目の答えを選び、「講座 6 へ」を押して `/tag/llm-eval` に着くまでを動画に撮る（診断に記事は要らない）。
3. DB を作り直して起動し、記事30本をローカル DB だけに作って公開する。手順は `docs/verification/local-mcp.md` の「手順」（`wrangler dev --local` を起動 → 管理画面でパスキーの管理者を作る → ローカル DB だけで使うトークンを発行 → 記事をローカル DB に作って公開）に従った。「予約の前の描画の確認」の節は、まだ merge されていない別ブランチ（`origin/ccr-4b03b147-6evnoc`、open の PR #103）の `docs/verification/local-mcp.md` にある。記事を作って公開する部分には、その別ブランチの `scripts/render-check.mjs`（PR #103 で open、このブランチには無い）を、スクラッチ側にコピーして使った（30本中30本合格）。このブランチには入れていない。
4. トップの新着の節を 390px と 1440px で撮り、項目を数える。トップ全体の画像は、スクロールせずに `fullPage: true` で撮った（ビューポートは 390x844 と 1440x900、deviceScaleFactor 1）。

## 結果

### 基準1: 新着の記事が3〜5本（合格）

記事30本を公開した状態で、`#latest`（見出し「新着の記事」）が1つ、`.latest__item` は **5件**（上限 `LATEST_POSTS_LIMIT = 5` どおり）。各件に講座の番号と名前、題、公開日があり、末尾に「記事一覧を見る」（`/posts`）があります。

| # | 講座の表示 | 題 | 公開日の表示 |
|---|---|---|---|
| 1 | 講座 02 / 構造化出力 | LLM の出力 JSON を zod で検証する【safeParse のエラーの読み方】 | 2026年11月28日 |
| 2 | 講座 02 / 構造化出力 | zod のスキーマから JSON Schema を作ってツール定義に使う【zod v4 の z.toJSONSchema】 | 2026年11月28日 |
| 3 | 講座 02 / 構造化出力 | 構造化出力のやり方を比べる【プロンプト指示、自作ツール、outputFormat】 | 2026年11月28日 |
| 4 | 講座 06 / LLM 評価 | LLM 評価で RAG の検索を採点する【Recall@k と MRR を TypeScript で】 | 2026年11月28日 |
| 5 | 講座 03 / RAG | 埋め込みを手元で作ってベクトル検索する【Transformers.js、API キー不要】 | 2026年11月28日 |

注意: 30本を一括で公開したため、公開日（`published_at`）は全件が同じ日（投入の間隔は数百ミリ秒）です。日付の表示だけでは並びを判別できません。表示は日本時間の日付で、この回は 2026-11-27T15:03Z 台に公開したため 11月28日 になります（前の回の記録は 11月27日 でした。同じ手順を深夜に再実行したためで、画像は今回のものに差し替えた）。

並び順の根拠は2つに分けて書きます。

- `test/latest-posts.test.ts` が確かめているのは `selectLatestPosts`（公開日の新しい順の並べ替え、5本までの絞り込み、公開日が無い記事の除外）です。`src/pages/index.astro` の21〜24行目にあるデータベースへの問い合わせ（`orderBy: { published_at: "desc" }`、`limit: LATEST_POSTS_LIMIT * 2` = 10）は、このテストの対象外です。
- 実際の画面までの並びは、この回の `latest-datetimes.txt`（新着の5件の `<time datetime>`、スラッグ、題）で示します。値はミリ秒まで降順です（15:03:42.275Z、41.683Z、41.132Z、40.571Z、39.967Z）。

コードの端の動きも書いておきます。公開済みの記事が1〜2本なら、節は1〜2件だけ出ます（3本に満たなくても節は隠れず、0本のときだけ隠れる）。「講座 NN / 名前」の表示は、入門ステップ講座のタグが付いた記事にだけ出ます。この30本はすべてタグが付いているので、5件とも出ています。

### 基準2: 0本の間は節が出ない（合格）

空の DB で、390px と 1440px の両方で `#latest` の要素数は **0**、「新着の記事」の文字列の出現数も **0**。HTTP でも `curl` で `id="latest"` が0件でした。

### 基準3: 診断の2つ目の答えから `/tag/llm-eval` へ（合格）

390px と 1440px の両方で次のとおりでした。

- 押す前: 答え1が選択中（`aria-pressed=true`）、`#rec-new` が表示、`#rec-pro` は非表示。
- 2つ目の答え「一度作ったが、本番レベルにしたい」を押した後: `aria-pressed=true`（答え2）、`#rec-new` は非表示、`#rec-pro` が表示。表示の文言は「おすすめ: 6「LLM 評価」と応用記事、特典のサンプルアプリ。 講座 6 へ 特典へ」。
- 「講座 6 へ」の `href` は `/tag/llm-eval`。押すと URL が `http://localhost:8787/tag/llm-eval` になり、見出し h1 は「LLM 評価」、`<title>` は「LLM 評価（入門ステップ講座 06） — ai-eng-blog」。

「特典へ」（`#gift`）のリンクも残っています。

## 動作確認の対象外

- 本番（Cloudflare）での表示は見ていません。ローカルの `wrangler dev --local` だけです。
- 記事の公開日が日ごとに分かれた状態（予約公開）での並びは見ていません（上の注意のとおり、全件が同じ日です）。
- 公開済みが1〜2本の状態と、講座のタグが無い記事の表示は、画面では確かめていません（コードを読んだ範囲です）。

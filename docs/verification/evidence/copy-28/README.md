## 結果

- 30本のすべてのコードブロック 592個で、ボタンを押してクリップボードを読み、原稿（`content/articles/*.md`）のフェンスの中身（`scripts/code-blocks.mjs` で取り出した値）と比べた。**592個とも1文字も違わなかった**。どの記事も、原稿のコードブロックの数と、描画された `pre` の数と、見えるボタンの数が同じだった。
- キーボード: ボタンにフォーカスが来て、Enter でも Space でも写せた。押すと `role="status"`・`aria-live="polite"` の要素に「コードをコピーしました」が入る（読み上げに伝わる）。2秒後にボタンの文字が「コピー」に戻った。
- JS を切ったページでは、見えるボタンは0個（押せないボタンを出さない）。
- 幅 390px と 1440px で、ページ全体の横スクロールは無い（scrollWidth が画面の幅と同じ）。

## 否定のレビューのあとの直し（2026-11-27）

- 代わりの経路（`navigator.clipboard` が使えない・拒まれたとき）で、一時の textarea にフォーカスが移ったまま戻らなかった → 押したボタンへフォーカスを戻すようにした。`writeText` が必ず拒む状態で Enter を押し、押した後もフォーカスがそのボタンにあることを確かめた。
- ボタンの名前がどれも「コピー」だった → 読み上げ用の名前を「bash のコードをコピー」のように、帯の言語（ファイル名があればファイル名）を入れた形にした。
- 印刷でボタンが出ていた → 印刷では隠す（印刷の emulation で `display: none`）。
- 直したあとも、30本の 592個とも原稿と1文字も違わなかった（上の結果を撮り直した）。
- 見た目の変化: 前は EmDash の `Code.astro` の色（背景 #1e1e1e、余白 16px、上下 24px）が記事ページの `.prose pre` の指定より優先されていた。部品を置き換えたので、記事ページの指定（背景 `--code-bg` #1a1d21、余白 20px、上の間 20px、等幅の書体 `--font-mono`）が効くようになった。サイトの配色に合う側にそろえたので、このままにしている。

# rag-chat: いちばん小さい RAG チャットのサンプル

手元の Markdown から質問に関係する段落を探し、その段落だけを根拠にして Claude に答えさせる TypeScript のサンプルです。

```
質問 ──▶ docs/*.md を読む ──▶ チャンクに分ける ──▶ BM25 で点数づけ ──▶ 上位 k 件
                                                                         │
                                         回答 ◀── Claude (Agent SDK) ◀──┘
```

- 検索（BM25）は TypeScript だけで書いてあり、外部サービスも使いません。オフラインで動きます。
- 答えの段は Claude Agent SDK（`query()`）で呼びます。API キーは使いません。Claude Code にログインしていないときは、検索の結果と Claude に渡す予定のコンテキストを表示し、ログインの方法を1行出して終了コード 0 で終わります。
- 同梱の `docs/` には、このサンプル自身の説明を書いた短い Markdown が 3 本入っています。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `src/chunk.ts` | Markdown を見出しと空行で区切り、400 文字以内のチャンクにまとめる |
| `src/bm25.ts` | トークン化（英数字は単語、日本語は 2 文字ずつの bigram）と BM25 検索 |
| `src/loadDocs.ts` | フォルダ内の `.md` を読んでチャンクにする |
| `src/answer.ts` | 取り出したチャンクを `<chunk>` タグで包み、Agent SDK の `query()` で Claude に送る |
| `src/cli.ts` | コマンドの入口。環境変数を読み、検索結果と回答を表示する |
| `test/*.test.ts` | チャンク分割・検索のテストと、モデルの呼び出しを差し替えて動かすテスト |

## 必要なもの

- Node.js 22.18 以上の 22 系、または 24 系（TypeScript をビルドせずに `node src/cli.ts` で直接実行します。型を取り除いて実行する機能が既定で有効になったのが 22.18.0 からなので、それより古い 22.x では `.ts` を読めずに止まります。`package.json` の `engines`（`^22.18.0 || ^24.0.0`）も同じ範囲にしてあり、範囲外の版で `npm ci` すると `EBADENGINE` の警告が出ます。23 系は動かして確かめていないので入れていません。動作確認は Node.js 22.23.4 と 24.22.3 で行いました）
- Claude に答えさせる場合だけ、Claude のプランのアカウントでログインした Claude Code（`claude` を起動して `/login`）。ログインが使えるプランの条件は [公式のヘルプ](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)（2026-11-14 確認）で確かめてください。API キーは使いません

## セットアップ

リポジトリから取った場合は `samples/rag-chat`、zip で受け取った場合は展開してできた `rag-chat` フォルダに移動してから実行します。

```bash
cd samples/rag-chat   # zip の場合は cd rag-chat
npm ci          # package-lock.json どおりに入れる（@anthropic-ai/claude-agent-sdk 0.3.322 など）
```

## 実行コマンド

```bash
npm run typecheck                 # tsc --noEmit で型チェック
npm test                          # node:test でテスト
npm start                         # 既定の質問で実行
npm start -- "RAG_TOP_K の既定値は？"   # 質問を指定して実行
```

Claude に答えさせる場合は、先に Claude Code にログインしておきます。`ANTHROPIC_API_KEY` が環境に入っているとログインより優先されるので、プランで動かすときは外してから実行します（同ヘルプ、2026-11-14 確認）。

```bash
unset ANTHROPIC_API_KEY
npm start -- "日本語の文章はどうやって検索していますか？"
```

### 環境変数

| 名前 | 既定値 | 説明 |
| --- | --- | --- |
| `ANTHROPIC_MODEL` | `claude-sonnet-5-5` | 使うモデル ID |
| `RAG_TOP_K` | `3` | Claude に渡すチャンク数（1 以上の整数） |
| `RAG_DOCS_DIR` | `docs/` | 読み込む Markdown フォルダ |

`.env.example` は変数の一覧です（API キーの行はありません）。このサンプルは `.env` を自動では読み込みません。

## 期待される出力

ログインしていないときの出力です。検索の結果までは同じで、そのあとに Claude に渡す予定のコンテキストと、ログインの案内が出ます。終了コードは 0 です。

```
質問: このサンプルは日本語の文章をどうやって検索していますか？
読み込んだチャンク数: 9 / 取り出した件数: 3 (top-k=3)

[1] 02-retrieval.md#1  score=10.700  見出し: トークン化
[2] 02-retrieval.md#0  score=8.266  見出し: 検索の仕組み（BM25）
[3] 02-retrieval.md#2  score=7.605  見出し: BM25 の点数

--- Claude に渡す予定のコンテキスト ---
...（省略）

Claude Code にログインしていないため、Claude への問い合わせは行わずに終了します。ログインするには `claude` を起動して `/login` を実行してください（検索部分は上のとおり動いています）。
```

ログインしているときは、検索結果に続けて `--- 回答 (claude-sonnet-5-5) ---` と回答本文、続けて `Agent SDK: claude_code_version=… apiKeySource=…`（起動メッセージの値）の行、最後に `ターン数` と `total_cost_usd（見積もり）` が表示されます。回答の文面は実行ごとに変わります。実際の出力は [`logs/real-run-2026-11-14.txt`](./logs/real-run-2026-11-14.txt) にあります。

### 実際に動かした記録

2026-11-14 に、答えの段まで実際に動かしました。環境は Linux の Claude Code クラウドセッション、Node.js 22.23.4、`@anthropic-ai/claude-agent-sdk` 0.3.322 です。動かした Claude Code は SDK に同梱の 2.1.322 で、起動メッセージの `apiKeySource` は `none`（API キーを使っていない）でした。`ANTHROPIC_API_KEY` は `env -u` で外して実行し、終了コードは 0 でした。ログの先頭に、起動メッセージの値を残してあります。

- この実行の認証は、セッションを動かすホストが渡したものです。読者の手元で `/login` したプランのログインとは経路が違うため、手元のログインでの実行は未確認です（確認は Issue #62 で扱います）。
- ログインが無い場合の表示（上の出力）は、`test/cli.test.ts` が `main` に差し替えたモデル呼び出し（`authentication_failed`）を渡して確かめています。実機でログインを外した状態では確かめられていません。

テストは、モデルの呼び出しを差し替えているので、ログインが無くても通ります。`npm test` は 14 件すべて pass します。

## 動かすのに要るもの（料金について）

Agent SDK を Claude のプランのログインで動かした分は、プランの利用枠から引かれます。使える範囲や条件はプランによって違い、変わることもあるので、[公式のヘルプ](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)（2026-11-14 確認）で確かめてください。表示される `total_cost_usd` は SDK が出す定価換算の見積もりで、請求額ではありません（型定義のコメントも "An estimate, not a billing statement" としています）。

1 回の質問で使う量は、システム指示・チャンク 3 件・質問を合わせた入力が数百〜2,000 トークン程度です。`RAG_TOP_K` を増やしたり大きな資料を使ったりすると増えます。

## 制限

- **言い換えに弱い**: BM25 は同じ文字が出てくるかどうかで点数をつけるので、「料金」と「価格」のような別の言葉は一致しません。本番では埋め込みモデル（ベクトル検索）との併用を検討してください。
- **日本語のトークン化は簡易版**: 2 文字の bigram なので、関係の薄いチャンクにも小さな点数がつきます。形態素解析は使っていません。
- **毎回すべて読み直す**: インデックスを保存しないため、実行のたびに全ファイルを読み直します。数百ファイル程度までを想定しています。
- **会話の履歴を持たない**: 1 回の実行で 1 問だけ答えます。続けて質問しても前の質問は覚えていません。
- **ストリーミングしない**: 回答は全部できあがってから表示します。
- **Claude Code のプロセスを起動する**: Agent SDK は Claude Code を子プロセスとして動かすので、1 回の質問にも起動の分の時間がかかります。
- **Markdown の構文はほぼそのまま**: 表やコードブロックも普通の文章としてチャンクに入ります。
- **回答の正しさは保証しない**: 資料だけで答えるように指示していますが、モデルが資料にないことを言う可能性はゼロではありません。表示される `source` を見て元の段落を確認してください。

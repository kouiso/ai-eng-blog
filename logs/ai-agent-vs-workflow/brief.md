# brief: ai-agent-vs-workflow

## C01 の1行

LLM の API を少し触った TypeScript の開発者が「AI エージェントとワークフローの違い」を調べたときに、次の手順を決めるのがコードか LLM かという違いを、同じ仕分けを2通りに書いて動かした実測（呼び出し回数、時間、見積もりの費用、途中で止まった問い合わせ）と、答えをコードで確かめられる時点の違いつきで答え、どちらを選ぶかの判断基準を示す記事。

## 読み終えた人ができるようになること

自分の処理をワークフローとエージェントのどちらで書くかを、手順を先に書き出せるかで決め、Agent SDK の `query()` で両方を書ける。

## 態度（guides/03 不在1）

手順を書き出せる処理はワークフローで書く。実測ではエージェントのほうが速くて安かったが、それでもこの仕分けはワークフローにする。理由は呼び出し回数が先に決まり、手順の間で答えの形を確かめられるから。

## 2026-11-10 の見直し（レビューの指摘への対応）

- エージェント版の題材が `claude-agent-sdk-first-agent`（#17）の例と同じ形（Glob と Read で3ファイルを読む、num_turns=5 の内訳、2回目の Glob の引数の違い）になっていた。エージェント版をワークフロー版と同じ仕事（3件の分類と、返金への返信の書き出し）に書き直し、num_turns の内訳と Glob の引数の説明を外した。この記事で見せるのは、同じ仕事をさせたときに、答えをコードで確かめられる時点が「1件ごと」と「全部の作業のあと」に分かれること。
- description が「止め方を実測で比べます」と約束していたが、エージェント側の停止条件（maxTurns）は実測していなかった。description を実測した内容（呼び出し回数と時間）に合わせ、比較の表に「途中で止まった問い合わせ」の行（実測）を足した。上限で止まったときの挙動は #18 にリンクする。

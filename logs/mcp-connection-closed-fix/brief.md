# brief: mcp-connection-closed-fix

## C01 の1行（誰の、どんな検索に答える記事か）

TypeScript で stdio の MCP サーバーを作った人が、Claude Code か SDK のクライアントから `MCP error -32000: Connection closed` でつながらず原因を調べたときに、エラーの意味と、サーバーの stderr から原因を3つに見分けて直す手順に答える。

## 上位記事を見たか

2026-11-02 に、Claude の WebSearch（米国向けの検索で、日本の Google の上位10件ではない）で「MCP error -32000 Connection closed 原因」を1回検索して、上位の題名と要約を見た。Google 日本の検索結果は見られていない。

見えたこと（判断の材料。記事の出典には使わない）:

- 上位は GitHub の個別の Issue と、原因を箇条書きで並べた第三者のガイド。「起動したプロセスが死んでいる」「設定のコマンドを端末で手で実行してみる」「venv と入口のパスの不一致」「環境変数の設定ミス」が挙がっている。
- SDK のクライアントが既定で渡す環境変数が6つに限られること、相対パスの登録が起動したフォルダで結果が変わることを、実行結果で見せている記事は見当たらなかった。
- 「端末で手で実行する」は、正しい stdio サーバーでも入力を待つか、標準入力が閉じていればそのまま終わるので、成否の見分けがつきにくい。そのため記事では、応答の有無で白黒がつく形にした。

この観察から、(1) エラーの意味を SDK のソースで確かめて書く、(2) stderr を拾う確認用のクライアントを道具として渡す、(3) 原因ごとに実行結果と直し方を並べる、(4) 手で確かめる方法は `initialize` の1行を送る形にする、と決めた。

## 書き手の態度（guides/03 不在1）

`Connection closed` という文面そのものには、原因の情報が1つも入っていない。原因はいつもサーバーの stderr にあるので、まず stderr を表示する道具を持つべき。原因の中では、環境変数が SDK のクライアントから渡らない件がいちばん気づきにくく、シェルでは設定してあるのに「未設定」と言われるので、最初に置く。

## 記事型と見出し骨格（guides/02 タイプ3 トラブル解決から写した）

テンプレート:

```
タイトル：【エラー名そのまま】の原因と解決方法
リード（最重要・3行以内）：エラーが何か、原因は何か。道筋を見せる
結論（先に解決策）：いちばん多い原因と直し方。変更前 → 変更後
原因の説明：なぜこのエラーが起きるのか
原因別の解決策：原因ごとに見出しを分ける。具体的なコードと手順
それでもダメなとき：切り分け手順、確認すべきログ
まとめ：チェックリスト形式で「確認すべきこと」
```

この記事の骨格:

- リード: `Connection closed` はプロセスが終了した知らせ、理由は stderr。原因3つと直し方の表（結論）。対象読者、コードの量、前の記事へのリンク
- H2 Connection closed はサーバーのプロセスが終わったという知らせ（原因の説明。SDK のソース、JSON-RPC の番号、stderr の扱い）
- H2 原因は確認用のクライアントで stderr を表示すれば読める（前提・環境、package.json、server.ts、check.ts。check.ts は起動するコマンドと引数を引数で受け取り、ツールの一覧だけを取るので読者のサーバーにも使える。最初の実行で原因1が出る）
- H2 原因1 サーバー自身が投げたエラーは文面が原因を指す（文面が名指しするものを用意する。環境変数のほかの例として無い設定ファイル。SDK が渡す変数、変更前 → 変更後、Claude Code の -e の登録と実行結果）
- H2 原因2 Cannot find module は起動するファイルのパスの誤り（書き間違い、原因1で登録した相対パスをホームフォルダで確かめる、絶対パスで登録し直す）
- H2 原因3 エラーの行が無ければサーバーが接続を始めていない（connect の書き忘れ、initialize を手で送る）
- H2 Connection closed 以外の文面は別の原因を指す（それでもダメなときに当たる。ENOENT、タイムアウト、stdout のログ、Inspector）
- H2 料金がかからない範囲
- H2 つながらないときに確かめる順番（まとめに当たる節。チェックリスト、問い、次の記事へのリンク）
- H2 出典

## 読み終えた人ができるようになること

`Connection closed` が出たときに、サーバーの stderr を表示して、環境変数、パス、接続の書き忘れのどれが原因かを見分け、SDK のクライアントと Claude Code の両方で直せる。

## 2026-11-10 の直し

レビューの指摘5件（check.ts が読者のサーバーを同じコマンドと環境変数で起動できない、サーバーが投げたエラーを環境変数に一般化していた、原因1の中の原因2への前方参照、Node.js の前提の版、内部リンクの文言）を受けて、check.ts を引数のコマンドで起動し一覧を取る形に変え、原因1の見出しとリードの表とまとめの手順を「文面が求めるもの」に直した。骨格の H2 の並びは変えていない。

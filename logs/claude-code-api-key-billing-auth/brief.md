# brief: claude-code-api-key-billing-auth

## C01 の1行

Claude Agent SDK か `claude -p` を自分の Claude プランで使っている TypeScript の開発者が、「プランで動かしているはずなのに API キーの従量課金で動いている」「Invalid API key が出る」と困って検索したときに、原因（環境変数 `ANTHROPIC_API_KEY` がプランのログインより先に使われること）、`apiKeySource` と `claude auth status` での見分け方、キーの出どころ別の外し方を、実行結果つきで答える記事。

この記事での見出し（作業の実況ではなく、内容で書く。エラー文 `Invalid API key` をタイトルと見出しに入れる）:

1. リード（原因は `ANTHROPIC_API_KEY`、従量で請求される、`apiKeySource` で見分けて外せば直る）
2. 結論: apiKeySource が none なら、プランで動いている（確かめる2つのコマンド、値の表、`unset`）
3. 原因: キーがあると、ログインより先に使われる（認証の順番、`-p` は聞かずに使う）
4. 無効なダミーのキーで Invalid API key を再現する（CLI。トークン数0）
5. Agent SDK では init の apiKeySource に出る（`check-auth.ts`、`subtype` だけ見ると見逃す）
6. キーの出どころ別の直し方（シェル、`.env`、コードの `env` オプション（変更前 `check-auth.ts` → 変更後 `plan-only.ts`）、設定の `env`）
7. 料金はどちらで動いたかで変わる（プランの利用枠、キーで動いた分の料金）、問いで終える
8. 出典、次の記事へのリンク、末尾の表記

テンプレートの「まとめ（チェックリスト）」は、結論の節（2）が確かめ方のチェックになっているので、独立した節にしなかった（冒頭の主張を結末で繰り返さないため。guides/09 §1-1 の7）。

## 読み終えた人ができるようになること

自分の Agent SDK と `claude -p` が API キーとプランのどちらで動いているかを `apiKeySource` と `claude auth status` で確かめ、キーがシェル、`.env`、設定のどこから来ていても外して、プランのログインで動かせる。

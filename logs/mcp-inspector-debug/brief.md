## 上位記事を見たか

2026-11-02 に、Claude の WebSearch（米国向けの検索で、日本の Google の上位10件ではない）で「MCP Inspector 使い方」を1回検索して、上位の見出しを見た。Google 日本の検索結果は見られていない。

見えたこと（判断の材料。記事の出典には使わない）:

- 日本語の上位は「MCP Inspector とは」と画面の使い方の記事で、起動は `npx @modelcontextprotocol/inspector`、画面の左側で Transport を選んでつなぐ、という v1 の画面の説明が中心。
- ポートを 5173 と 3000、または 6274 と書く記事が混ざっていて、版によって説明が食い違っている。
- CLI モードを中心に書いた記事、v2（2026-07-28 以降の版）の画面と CLI の終了コードを書いた記事は、上位の見出しには見当たらなかった。

この観察から、記事は (1) 版を 2.13.0 に固定して書く、(2) v1 から変わった点（プロキシのポート 6277 が無い、Node.js 22.19.0 以上）を短く書く、(3) CLI を先に置き、終了コードと引数の型の落とし穴まで実行結果で見せる、と決めた。

## 書き手の態度（guides/03 不在1）

最初に覚えるのは CLI のほう。結果がテキストで残り、終了コードで成否がわかるので、作り直すたびに同じコマンドを打ち直せる。画面は、やり取りの JSON-RPC を目で追いたいときに開く。CLI には `--tool-arg text=2026` が数値として送られる落とし穴があり、手元で踏んだので記事の中心に置く。

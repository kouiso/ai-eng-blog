# code/

記事 `content/articles/llm-eval-dataset-from-logs.md` に載せたコードを、記事の形のまま置いています。

| ファイル | 記事の中の位置 |
|---|---|
| `package.json` | 「動かした環境と作業フォルダ」 |
| `logs.jsonl` | 「見本のログ logs.jsonl は1行に1件の JSON」 |
| `build-cases.ts` | 「build-cases.ts はログを読んでテストケースを選ぶ」 |
| `check-cases.ts` | 「改行を含む回答も1行に収まる」 |

記事と1文字も違わないことは `../lint/check-code-and-outputs.py` で確かめています（結果は `../lint/check-code-and-outputs.txt`）。依存パッケージは無いので `npm install` はしません。`logs.jsonl` は手で作ったログの見本で、実際のアプリのログでもモデルの出力でもありません。8行目は、書き込みの途中で切れた行の見本として、わざと JSON の途中で切っています。メールアドレスは例示用に予約された `example.com` のものです。

`extra/` は記事に載せない確認用です。

- `run-all.sh`: 作業場所に記事どおり `eval-dataset` フォルダを作り、上のファイルを置いて、記事の順にコマンドを実行し、`../run/01.log`〜`12.log` を書きます。作業場所にはセッションの一時フォルダを使い、終わったら消しました。ログの中の作業場所のパスは `<work>`、このフォルダのパスは `<code>` に置き換えています。
- `dedup-variants.ts`: 重複を見分けるキーの作り方を4通りに変えて、残る件数を数えます（`../run/06.log`）。記事のキーで12件、空白を1つにまとめるだけのキーで13件、NFKC なしで13件、そのまま比べると14件でした。全角の疑問符が NFKC で半角の「?」に、全角の空白が半角の空白になることも表示します。
- `quota.ts`: カテゴリごとの件数を、`Math.max(1, …)` がある場合と無い場合で比べます（`../run/07.log`）。無い場合は `payment` が0件になり、合計は5件です。ある場合の合計は6件です。
- `tsconfig.typecheck.json`: TypeScript 7.0.2 と `@types/node` 22.20.5 で型を確かめる設定です（`../run/10.log`）。記事の作業フォルダとは別のフォルダに `--no-save` で入れました。Node.js は型を検査せずに `.ts` を実行するので、別に確かめています。

ほかの確認用の実行は `run-all.sh` の中に書いています。

- `../run/08.log`: `cases.jsonl` の最後の1バイト（改行）だけを削ったファイルを作り、`wc -l` で数えます。最後の改行がある元のファイルは 6、削ったファイルは 5 でした。
- `../run/09.log`: `question` の欄が無いログ1行（JSON としては読める）を `build-cases.ts` に渡します。`mask` の中で `TypeError` になり、終了コード 1 で止まりました。
- `../run/11.log`: ネットワークの無い名前空間（`unshare -rn`）で、記事の `node` コマンド2つを動かした記録です。外への `fetch` が失敗する環境でも、出力は `02.log`、`04.log` と同じでした。
- `../run/12.log`: OS とアーキテクチャの確認（`uname -sm`）です。

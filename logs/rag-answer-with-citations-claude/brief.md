# brief: rag-answer-with-citations-claude

## C01 の1行

BM25 などで RAG の検索部分を作った TypeScript の開発者が、「検索結果をモデルに渡して、出典つきで答えさせる方法」を探して検索したときに、番号を付けた資料をプロンプトに入れ、回答と出典の番号と引用文を JSON で受け取り、その番号と引用文が渡した資料に本当にあるかをコードで確かめる手順を、自分の Claude プランで動かした実行結果つきで答える記事。

検索語そのものは、CSV が無いので未確定（G10）。

## 検索意図のタイプ

やり方（How-to）。guides/01 §1 の表で、合う記事型はチュートリアル。`content/plan.md` #14 の仮の分類も「やり方」。

Google（日本）の上位10記事は見ていない。このセッションでは日本向けの Google 検索の結果を取得する手段が無かった。検索意図は、仮タイトルが「出典つきで回答させる」で、手順とコードを求める人が来る前提から、やり方に決めた。

## 記事型

チュートリアル（guides/02 タイプ1）。

テンプレートの見出し骨格（guides/02 から写す）:

```
タイトル：【環境/バージョン】〇〇で△△を作る方法

リード
  - 何が作れるか（完成形を最初に見せる。画像やデモがあれば理想）
  - 対象読者（前提知識：例「Reactの基本がわかる人」）
  - 所要時間の目安

前提・環境
  - 必要なもの（Node.jsのバージョン、インストール済みパッケージ）
  - コードの全体像 or 完成リポジトリへのリンク

手順（番号付き、1ステップ1見出し）
  1. セットアップ
  2. 〇〇の実装
  3. △△の実装
  ※ 各手順に「コード」と「その時点の実行結果」をセットで
  ※ ハマりやすい所は「⚠️ ここで詰まりやすい」と補足

動作確認
  - 実際に動かした結果（スクショ or 出力）

まとめ
  - 完成したものの再確認
  - 次にやれること（発展)・関連記事へのリンク
```

この記事での見出し（作業の実況ではなく、内容で書く。guides/02 共通原則4）:

1. リード（何が動くか、出典の番号と引用文をコードで確かめること、プランで API キーなしで動くこと）
2. 前提（Node.js、プラン、`ANTHROPIC_API_KEY` を外す）
3. セットアップ（SDK を1つ入れ、#11 の検索器の3ファイルをそのまま置く）
4. 検証の関数 `verify.ts`（番号が渡した資料にあるか、引用文がその資料にあるか、答えられないのに出典が付いていないか）と、手で作った誤りの見本で動きを見る
5. 回答させるコード `ask.ts`（番号を付けた資料、短い `systemPrompt`、`tools: []`、`outputFormat`）
6. 動作確認（答えがある質問、答えが無いのに関係のありそうな資料が並ぶ質問、資料が1件も見つからない質問）と、5回ずつ動かした結果
7. 料金とプランの利用枠、確認すること、問い
8. 出典、前後のリンク、末尾の表記

## 読み終えた人ができるようになること

自分の検索結果に番号を付けてモデルに渡し、回答と出典を JSON で受け取って、出典の番号と引用文が渡した資料にあるかをコードで確かめ、資料に答えが無いときに「答えられない」を返させられる。

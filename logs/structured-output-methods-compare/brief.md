# brief: structured-output-methods-compare

## C01 の1行

LLM の出力を JSON で受け取りたい TypeScript の開発者が、「構造化出力のやり方はどれを選べばいいか」を探して検索したときに、同じ抽出の作業をプロンプト指示、自作ツール、`outputFormat` の3通りで Claude Agent SDK に10回ずつやらせた実測（取り出せた数、スキーマに合った数、正解の数、トークン、定価換算の見積もり、コードの行数）と、その結果から決めた選び方を答える記事。

検索語そのものは、CSV が無いので未確定（G10）。

## 検索意図のタイプ

比較（Compare）。guides/01 §1 の表で、合う記事型は比較記事。`content/plan.md` #10 の仮の分類も「比較」。

Google（日本）の上位10記事は見ていない。このセッションでは日本向けの Google 検索の結果を取得する手段が無かった。検索意図は、計画のタイトル（「構造化出力のやり方を比べる」）から、選び方を知りたい人が来る前提で比較に決めた。

## 記事型

比較（guides/02 タイプ4）。

テンプレートの見出し骨格（guides/02 から写す）:

```
タイトル：〇〇と△△の違いと使い分け【〇〇年版】

リード
  - 結論を先に：「急ぐなら〇〇、△△なら□□」
  - 比較の観点を予告（速度・学習コスト・エコシステム等）

比較表
  - 観点を縦、選択肢を横に並べた一覧表
  - ◎○△× より、具体的な数値・事実で

観点ごとの詳細
  - 表の各行を、コードや実例で深掘り
  - 「速度」なら実測値、「学習コスト」なら具体的な躓きポイント

ケース別の選び方
  - 「個人開発なら」「チームなら」「大規模なら」
  - 読者が自分の状況で選べるように

まとめ
  - 結局どれを選ぶか、を言い切る（中立で逃げない）
```

この記事での見出し（内容で書く。guides/02 共通原則4）:

1. リード（結論: 迷ったら `outputFormat`。比べた観点）
2. 比較表（実測の数字）
3. 前提（Node.js、プラン、ログイン）
4. 比べた作業と共通の部分（`cases.ts`、`common.ts`）
5. (a) プロンプト指示と `JSON.parse`
6. (b) 自作ツール（`strictMcpConfig` を外したときの見積もりの数字。指定の意味は #16 に任せる）
7. (c) `outputFormat`（`target: "draft-7"` は2段落で触れ、理由は #6 に任せる）
8. 動かした結果（10件ずつ2回）
9. ケース別の選び方
10. 出典、次の記事へのリンク、末尾の表記

## 読み終えた人ができるようになること

3つのやり方の、取り出せる率、追加でかかるターンとトークン、書くコードの量の違いを実測で知り、自分の用途でどれを使うかを決めて、そのコードを Agent SDK で動かせる。
